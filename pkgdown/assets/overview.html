SurveyDokum

Semi-automated documentation for survey datasets. R computes the descriptive statistics and detects each variable's type, and a language model running on your own machine turns them into a readable description, a help page and a codebook.

This page shows what the package is made of and in which order its parts are used. Author: Maria Valaste, University of Helsinki.

20user-facing functions, all prefixed sd_
3output languages: Finnish, English, Swedish
7input formats: csv, tsv, xlsx, xls, sav, dta, rds
137automated tests (testthat)
Workflow

Five steps from raw data to finished documentation

The design has two stages. First R does all the computation and checking, then a language model writes prose from the results. The model never calculates anything and never sees the raw data. Select a function to see what it does.

R computes · same result every time
statistics only
Language model writes · local Ollama
1 · READ

Load the data

The file becomes an sd_data object: the data and its metadata (roles, labels, missing-value codes) travel together.

2 · PREPARE

Clean and classify

Missing-value codes (e.g. −9, 99) are flagged, and each variable gets a guessed role. You can correct any guess by hand.

3 · SUMMARISE

Compute statistics

By role: distributions, means, frequencies. For open-ended answers, only length and counts.

4 · WRITE

Description and help page

The statistics are formatted into a prompt, and the model writes text from them in the chosen language.

5 · KEEP CURRENT

Update when data changes

New variables get descriptions while approved text stays untouched. Row counts are fixed without the model.

The codebook (sd_codebook) and DDI export (sd_export_ddi) are produced directly in R, with no language model.
Dashed: optional RAG context from your own reference material.

  Privacy
  
What the language model sees, and what it never sees

  
The model runs on your own machine through Ollama, so nothing is sent to an external service. On top of that, the model only receives the statistics R has computed. The content of open-ended answers always stays out of the prompt.

  

    

      
Goes into the prompt

      
    
        
  • Variable name, label and detected role
    • 
        
  • Frequencies and value labels for Likert and categorical variables
    • 
        
  • Mean, standard deviation, min and max for continuous variables
    • 
        
  • For open-ended answers: average length in characters, number of distinct answers and number missing
    • 
        
  • Optionally: excerpts from your own reference material (RAG)
    • 
      

    

    

      
Never goes in

      
    
        
  • Individual response rows
    • 
        
  • The text of open-ended answers, not even as quotes
    • 
        
  • Respondent ID values
    • 
      

      
Model output is always reviewed before it is saved: the functions that write files run in preview mode by default (dry_run = TRUE).

    

  






  Variable roles
  
Every variable gets a role, and the role decides what is computed

  
Below is the package's example dataset survey_data: a workplace wellbeing survey with 200 respondents and 17 variables, coloured by detected role. The codebook treats Likert items that share a name prefix as one scale. The variable names are Finnish, as in the original data.

  

    

      

      

        
tt · 4 items

        
joh · 3

        
imu · 3

      

    

  

  

    
id
Name contains id or tunnus, or every value is unique.

    
nominal
Text or factor variable with repeated values.

    
likert
Whole numbers, 2–11 distinct values, range of 10 or less.

    
continuous
Any other numeric variable.

    
text
Over half the values unique, or average length over 30 characters.

    
date
Column is a date or timestamp type.

    
weight
Numeric, with paino, weight or wt in the name.

    
unknown
None of the above.

  

  
Order matters: run sd_set_missing() before sd_detect_roles(). Otherwise a code such as 99 stretches the range of a 1–5 scale, and the Likert item is classified as continuous.






  What you get
  
Outputs and where they are saved

  
Each dataset you document gets its own small R package. SurveyDokum fills in its contents, while the package skeleton and the website come from the standard usethis and pkgdown tools.

  Maintenance
  
When the data changes

  
There is no need to regenerate everything, which would throw away text you have already reviewed. First check quickly what has changed, then update only that.

  

    

      New variables?
      
For example a scale score such as tt_mean, or questions from a new wave.

      

        
sd_check_documentation_current() lists undocumented variables. No language model.

        
sd_update_roxygen() asks for descriptions of the new variables only. Existing descriptions, the title and @details stay as they are.

        
The variable count on the @format line is updated, and the old file is kept as a .bak backup.

      

    

    

      More respondents?
      
Same questions, a new survey round.

      

        
sd_check_row_count() compares the documented row count with the data. No language model.

        
sd_update_row_count() fixes the number on the @format line. A row count has one correct value, so no model is needed.

        
If the change is large, rerun sd_document(), since the description is based on the whole dataset.

      

    

  






  Quick start
  
The whole path at a glance

  
You need R, the packages usethis, devtools, roxygen2 and pkgdown, plus ellmer, haven, readxl and codebook. The language-model steps also need Ollama with a model pulled, for example ollama pull gemma3:12b. Detailed guides ship with the package in Finnish, English and Swedish.


# 1. A new package for the dataset (opens in a new RStudio window)
usethis::create_package("path/MySurvey")
usethis::use_data_raw("aineisto")

# 2. Read, clean and detect roles
library(SurveyDokum)
aineisto <- sd_read("data-raw/my_data.sav")
aineisto <- sd_set_missing(aineisto, codes = c(-9, -1))
aineisto <- sd_detect_roles(aineisto)
sd_summarise(aineisto)                         # check the statistics

# 3. Store the data in the package
survey_data <- sd_get_data(aineisto)
usethis::use_data(survey_data, overwrite = TRUE)

# 4. The language model writes (review before saving)
sd_document(aineisto, language = "en",
            save_to = "inst/methodology/description.txt")
sd_generate_roxygen(aineisto, "survey_data", language = "en",
                    dry_run = FALSE)
devtools::document()

# 5. Codebooks and website
sd_codebook(aineisto)
sd_export_ddi(aineisto, file = "codebook.xml")
pkgdown::build_site()
